# Приёмка и план проверок

Статус: тесты **специфицированы, не выполнены**. Приложения в передаваемом репозитории нет. [test-cases.json](test-cases.json) даёт устойчивые TEST-ID для каждого требования и каждого адаптера; [backlog.json](backlog.json) связывает их с задачами. Настоящий документ задаёт общие и сквозные критерии.

## Уровни

1. **Domain/unit.** Даты, state machines, price precedence, decimal money, refund balance, permitted transitions. Табличные примеры считают ожидаемое значение вручную, а не тем же методом, который тестируется.
2. **PostgreSQL integration.** Реальная поддерживаемая версия БД, роль приложения, RLS, composite FK, exclusion/race, transaction rollback, outbox atomicity. In-memory DB не доказывает эти свойства.
3. **API contracts.** Проверка OpenAPI request/response и неизвестных полей, idempotency request hash, ETag, scopes, file download, error redaction, pagination.
4. **Browser E2E.** Основные задачи по дизайн-макетам: mouse/keyboard/touch, ширины 360/768/1440/1920 px, 100% и 200% zoom, Cyrillic typography, long labels, loading/empty/error/read-only/conflict. Внешние записи только sandbox.
5. **Adapter contract/sandbox.** Настоящие согласованные схемы провайдера, подписи, порядок, лимиты, отмены и поддерживаемые поля. Fixtures синтетические либо юридически разрешённые и обезличенные.
6. **Reliability/security/load.** Fault injection, restore, tenant isolation, auth abuse, PII leakage, latency, большие диапазоны календаря и длительные exports.

## Golden dataset для финансов и отчётов

Использовать синтетические stay/даты из [synthetic-scenarios](../data/synthetic-scenarios.json). Добавить отдельно: проживание 2 ночи × 4 800 ₽ = 9 600 ₽, услуга 600 ₽, скидка 200 ₽ → начислено 10 000 ₽. Оплачено 6 000 ₽ → долг 4 000 ₽. Залог 5 000 ₽ учитывается отдельно. Возврат 1 000 ₽ без credit-note → долг 5 000 ₽. Credit-note 1 000 ₽ после возврата → долг 4 000 ₽. Комиссия 1 200 ₽ не меняет долг гостя. Каждый шаг проверяет debit=credit и отсутствие второго эффекта при повторе. Это искусственный пример, не данные заказчика.

Occupancy = проданные ночи / доступные ночи выбранной методики; ADR = выручка проживания / проданные ночи; RevPAR = выручка проживания / доступные ночи. Период, отмены, блокировки, бесплатные ночи и единицы измерения фиксируются в словаре отчёта; UI указывает методику. Не включать залог, сервисный расход и оплату SaaS в выручку проживания.

## Доступность интерфейса

Табличные/календарные клетки имеют текстовую дату/объект/статус; цвет не единственный носитель смысла. Focus не уходит за виртуализованное окно; логическая позиция восстанавливается после закрытия drawer. Диалог удерживает focus и возвращает его инициатору. Escape закрывает безопасное состояние; несохранённый черновик требует явного решения. Выделение дат и перенос имеют форму с date inputs как альтернативу drag. Toast ошибки не единственный доступный текст, live region объявляет сохранение/ошибку. `prefers-reduced-motion` отключает некритичные переходы. Проверять контраст по целям WCAG 2.2 AA из дизайн-спецификации, а не только автотестом.

## Доказательства и критерий готовности задачи

Requirement → screen/state → task → test → конкретный прогон. Доказательство содержит commit, environment, schema version, synthetic fixture version, expected/actual, reviewer/date; screenshots строго без реальных ПД. «Не удалось проверить из-за доступа» имеет статус blocked и dependency, не passed. Внешний протокол тестируется в разрешённом контексте; никакой live записью в аккаунте первого клиента во время исследования.

К выпуску не допускаются открытые дефекты потери/дублирования денег и броней, изоляции tenant, раскрытия ПД, обхода прав, невосстановимых backup или ложного connected. Незначительные визуальные дефекты могут иметь согласованный срок, но обязательный сценарий не считается готовым без его substantial states и доступного способа выполнения.
