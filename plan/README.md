# План реализации и выпуска

Начать с [порядка выпуска](release-plan.md), затем взять первую доступную задачу в [backlog](backlog.md). Полные машинно-читаемые карточки находятся в [backlog.json](backlog.json), конкретные проверки в [test-cases.json](test-cases.json), стратегия и блокирующие проверки в [testing.md](testing.md).

[Единая таблица трассировки](../requirements/traceability.csv) связывает каждое требование с исходником/PNG экрана, состояниями, этапом, задачей, проверкой и интеграционными зависимостями. [Проверка связей](traceability-validation.json) подтверждает существование ссылок, не готовность будущего приложения.

Статус всех задач: специфицированы, разработка не выполнена. В результате этой работы нет frontend/backend, рабочих API-подключений и промышленной миграции. Подготовленный набор достаточен для начала реализации доменного ядра, интерфейсов и стендов; внешние договоры/доступы закрываются параллельно по [воротам выпуска](release-plan.md).

Не считать прохождение MVP готовностью полного паритета. Полнота определяется реестром требований, исследованными возможностями интеграций, дизайн-покрытием и закрытыми приёмочными проверками. Недоступная функция остаётся в реестре с причиной и способом проверки.
