# Инструменты подготовки материалов

Эти скрипты создают и проверяют статические материалы передачи. Они не являются приложением, API-сервером или коннекторами и не должны обращаться к клиентскому аккаунту/закрытой базе.

## Состав и зависимости

| Скрипт | Назначение | Зависимости |
|---|---|---|
| [build_design.py](build_design.py) | Формирует редактируемые SVG, карту/индекс экранов, токены и используемые SVG-ассеты | Python 3, Pillow; локальный Golos Text |
| [design_sections.py](design_sections.py) | Вспомогательный модуль отдельных композиций статичных экранов; импортируется build_design.py | Та же среда Python; отдельный запуск не требуется |
| [render_design.mjs](render_design.mjs) | Преобразует SVG в PNG и растровые favicon | Node.js; `@resvg/resvg-js` 2.6.2 из локального `.artifact-tools/` |
| [build_handoff_details.py](build_handoff_details.py) | Формирует подробные декларативные материалы экранов и тексты передачи | Python 3; использовать зависимости, указанные в заголовке скрипта |
| [verify_materials.py](verify_materials.py) | Проверяет комплект, JSON/CSV, локальные ссылки/ID, структуру SVG/PNG, признаки секретов и отсутствие приложения | Python 3.9+, стандартная библиотека; рабочая среда 3.12 |
| [review_design.py](review_design.py) | Собирает контактные листы, проверяет границы текста и семантический контраст; не проверяет runtime UI | Python 3, Pillow; локальный Golos Text |

Версия рендерера проверяется по установленному пакету; локальный manifest может содержать совместимый диапазон. Для воспроизводимого экспорта использовать зафиксированную проверенную 2.6.2, а не произвольно обновлять зависимости. `.artifact-tools/` — локальная служебная среда, не исходник SaaS и не часть поставляемых клиентских данных.

Перед запуском прочитать заголовок и пути вывода конкретного скрипта. Генерация может перезаписать подготовленные SVG, PNG, индексы и JSON. Ручную содержательную правку нужно перенести в канонический вход/генератор либо сохранить согласованным изменением до новой генерации. Пользовательские/приватные файлы входами этих инструментов не являются.

## Порядок повторной сборки

Проверенная среда передачи: Python3.12.14, Pillow12.3.0, Node24.19.0, resvg2.6.2. На чистой машине зависимости графических инструментов устанавливаются отдельно; читать готовые материалы можно без них:

```powershell
python -m pip install -r tools/requirements.txt
npm install --prefix .artifact-tools --no-save --ignore-scripts @resvg/resvg-js@2.6.2
```

Из корня репозитория с доступными Python/Node и установленными зависимостями:

```powershell
python tools/build_design.py
node tools/render_design.mjs
python tools/build_handoff_details.py
python tools/review_design.py
python tools/verify_materials.py --write-report
```

Сначала формируются векторные исходники и карта, затем PNG, затем подробности экранов и итоговая проверка. Генератор подробностей не заменяет продуктовую спецификацию или исследовательские доказательства. После изменения генератора нужно осмотреть затронутые экспорты и обновить [визуальный протокол](../design/visual-qa.md).

review_design.py сохраняет контактные листы и geometry-and-contrast.json в design/review. Он не проверяет все наложения и интерактивную доступность: требуется визуальный просмотр и будущая проверка рабочего интерфейса.

## Проверка без перегенерации

```powershell
python tools/verify_materials.py
```

По умолчанию проверка читает материалы и печатает результат. `--write-report` записывает только [plan/validation-report.json](../plan/validation-report.json). Поддержан `--root` для явного корня набора. Код завершения: 0 — нет ошибок/предупреждений, 1 — ошибки, 2 — предупреждения. Отчет выводит расположение и правило; секретные совпадения не печатаются.

Статический валидатор не выполняет runtime-приемку, финансовые операции, синхронизацию, миграцию или проверку соответствия законам. Такие проверки определены в будущем [плане тестирования](../plan/testing.md) и воротах выпуска.
