# Спецификация интерфейса

Версия 1.0 · 24.09.2026. Это передача дизайна, а не работающий интерфейс. [Галерея](README.md), [карта экранов](screens.json), [контракты экранов](screen-specs.json), [готовые тексты](copy.json), [токены](tokens.json), [ассеты](../assets/README.md). Названия полей и сценарии в SVG конкретны, все значения вымышлены. Футер с ID и пометка о макете не входят в продукт.

## 1. Смысл и навигация

Рабочий интерфейс рассчитан на ежедневные операции команды: найти свободные даты, принять бронь, проверить заезд, деньги и доставку в каналы. Главный экран после входа — шахматка. Для горничной стартовый экран — назначенные задачи. Для бухгалтера — платежи. Предыдущий доступный раздел можно восстановить только внутри той же организации.

| Пункт | Экраны | Основной переход |
|---|---|---|
| Шахматка | SCR-CAL-01…04 | Полоса → краткая карточка → SCR-RES-03; диапазон → SCR-RES-02 |
| Бронирования | SCR-RES-01…12 | Реестр, заезды/выезды, источники, услуги, подборки, модуль, партнёры |
| Объекты | SCR-OBJ-01…06 | Объект → номера/правила/реквизиты/каналы |
| Цены и правила | SCR-RTE-01…09 | Дневная сетка → массовый расчёт → подтверждение |
| Гости | SCR-GST-01…05 | Профиль → брони, документы, согласия и договор |
| Финансы | SCR-FIN-01…08 | Реестр → исходный платёж → возврат/чек; залоги отдельно |
| Отчёты | SCR-REP-01…04 | Период → фильтры → расшифровка → экспорт |
| Задачи | SCR-OPS-02,03,05,06 | Назначение → выполнение → проверка; начисления и счётчики |
| Каналы | SCR-INT-01…04 | Допуск → сопоставления → тесты → состояние/конфликты |
| Сообщения | SCR-MSG-01…06 | Событие → диалог либо шаблон → предпросмотр → доставка |
| Сотрудники | SCR-IAM-03 | Приглашение → область объектов → права → отзыв |
| Настройки | SCR-ORG-01,02; SCR-MIG-01…03; SCR-BILL-01…04 | Организация, импорт, подписка |
| Контроль платформы | SCR-OPS-01,04,07 | Отдельный разрешённый контекст, причина и срок доступа |
| Вход | SCR-IAM-01,02 | Регистрация/подтверждение → организация; восстановление/MFA |

Публичный модуль SCR-RES-09 и кабинет гостя SCR-GST-03 не содержат бокового меню команды и переключателя организаций. Подборка SCR-RES-08 имеет внутренний редактор и публичный просмотр по ограниченной ссылке. Ссылка партнёра даёт только согласованный набор занятости без гостевых контактов. Модальные окна сохраняют контекст списка; глубокая ссылка на бронь открывает полную карточку. Back возвращает фильтры, положение прокрутки и выбранную строку.

Переключатель организации всегда виден в шапке команды. При переключении закрыть карточки, отменить незавершённые запросы, очистить данные предыдущего tenant; предупредить о несохранённом черновике. Поиск Ctrl/Cmd+K ищет только доступные записи текущей организации. Название скрытого объекта не появляется в подсказке, ошибке или пустом результате.

## 2. Шахматка

### Геометрия и чтение

В обычном макете: боковая панель 184 px, шапка 64 px, строка объекта 56 px, день 79 px, подписи объекта 244 px. Компактный режим: строка 40 px; крупный: 72 px. Цена в свободной ячейке, полоса проживания выше цены; при отсутствии права на деньги цена и индикатор оплаты исчезают без пустых сумм. Цвет сопровождается текстом и отличимым краем; заявки имеют пунктирный/подчёркнутый контур и подпись «Даты свободны». Заявка не уменьшает доступность. Не помещающийся текст обрезать с многоточием, полный доступный текст открыть фокусом/подсказкой. Источник показывать текстом, не требовать узнавания логотипа.

Верхние даты закреплены при вертикальной прокрутке, названия строк при горизонтальной. Их пересечение располагается выше обоих слоёв. Одна область прокрутки, без вложенного горизонтального скролла страницы. Сегодня выделено линией и словом; выходные имеют фон, не смысл занятости. Края полосы у границы окна отмечают продолжение; подпись содержит полные даты. Локальная ночь — полуинтервал [заезд, выезд), время заезда/выезда показывается отдельно. Буфер подготовки отличим штриховкой и подсказкой, не увеличивает оплаченные ночи.

### Выбор и переход

1. Кнопка даты открывает календарь выбора месяца и текстовое поле ДД.ММ.ГГГГ. Сегодня возвращает начало видимого окна, стрелки перемещают на ширину окна. Периоды 7/14/30 дней, ручной диапазон ограничен согласованным запросом; большой период подгружается частями.
2. Клик свободной ночи начинает выбор на одну ночь. Shift+клик продолжает до второй даты включительно для ночей; форма показывает реальный выезд на следующий день. Повторный клик/Enter открывает форму. Escape снимает выделение. Даты можно всегда ввести в форме без выбора мышью.
3. При drag диапазона показывать контур и подсказку «24–27 сентября · 3 ночи». Пока кнопка мыши удержана, данные не записываются. На отпускании открывается форма с объектом/датами. Выбор через занятую ночь помечается конфликтом; исключения из запрета пересечения отсутствуют.
4. Клик по броне открывает [боковую карточку](source/VAR-RES-DRAWER.svg) 516 px. Фокус на заголовке, далее действия. Полная карточка доступна отдельной кнопкой. Закрытие возвращает фокус исходной полосе. Клик по заявке не показывает её как занятую ночь.
5. Перетаскивание существующей брони допустимо как дополнение на desktop с правом изменения: временный контур → диалог старый/новый объект, даты, цена и правила → подтверждение. Сохранения в момент drop нет. Альтернатива «Изменить проживание» открывает те же поля и расчёт. На touch перетаскивание не обязательно, долгий tap не создаёт скрытого действия.

Строка нераспределённых броней категории показывает потреблённую квоту. Выбор номера переносит уже существующее размещение, не создаёт второй расход квоты. Сервер технически удерживает подходящую единицу; UI не обещает любой номер на всём диапазоне. Если доступна лишь перестановка нескольких броней, показать план и подтвердить его целиком либо предложить другой вариант. Никогда не скрывать внешний конфликт ради зелёной ячейки.

### Масштаб и свежесть

При 1 000 объектах показывать только видимые строки и ограниченный буфер; поиск/фильтры выполняются по всему доступному набору. Закреплённый объект остаётся в своей явной группе. Фокус строки не теряется при виртуализации, экранный диктор сообщает название, дату, цену/занятость и позицию. Количество результатов и действующие фильтры видны. «Нет объектов» отличается от «По фильтрам ничего не найдено».

Полоса свежести: время последнего чтения и доставка по каждому каналу. Локальное сохранение не означает публикации в OTA. Офлайн только ранее разрешённая обезличенная занятость, без контактов, сумм и кодов; TTL/инвалидация по [доступу](../architecture/access-control.md). Новые брони и изменения офлайн запрещены. После восстановления связи запросить свежие данные перед записью.

## 3. Бронь, цена и финансы

Форма SCR-RES-02: объект или категория, источник, заезд/выезд, взрослые/дети с возрастом, главный гость, контакт, тариф, услуги, комментарий. Обязательность контакта зависит от доставки/канала; внутренней заметке не нужен email. Кнопки «Сохранить заявку» и «Подтвердить бронь» имеют разный результат и явное пояснение про даты. Сначала синхронная проверка полей, затем свежий расчёт, затем серверная проверка доступности и версий. Ошибки полей выводятся рядом и в кратком списке сверху; введённые данные сохраняются в текущей сессии, паспорт/секрет не сохранять в localStorage.

Цена раскладывается по ночам, доплатам, скидкам, услугам и отдельному залогу. Quote живёт 10 минут (проектное значение); hold прямого модуля 15 минут (проектное значение), часы истечения показываются отдельно. Quote не удерживает место. Принятая стоимость не меняется от нового тарифа. Пересчёт показывается до согласия. Истёкший hold + поздняя успешная оплата ведут в очередь сверки, а не в автоматическое вытеснение другой брони.

Статусы проживания, оплаты, залога, уборки и доставки отдельны. «Подтверждена» не значит «Оплачена». Архив — признак видимости, не отмена. Возврат из архива сохраняет статус; восстановление отменённой брони заново проверяет доступность. No-show сохраняет историю с нулём фактических ночей. Досрочный выезд сохраняет оказанные ночи и пересчитывает будущее по условиям. История показывает кто/когда/до/после/основание с ограничением персональных полей.

Отмена: причина → предварительный расчёт аннулируемых начислений/штрафа/баланса по принятой политике → отдельное подтверждение освобождения дат → предложение отдельного возврата. При изменённой версии повторить расчёт. Произвольная сумма штрафа не принимается как готовый результат клиента; отклонение требует специального права и основания. Бронь OTA отменяется только разрешённым процессом, пока канал не подтвердил, подпись «Ожидает подтверждения канала».

На финансовых экранах сумма брони, зачтённые платежи, переплата/долг и залог раздельны. Формулы в [контракте цены и ledger](../architecture/pricing-ledger.md). Возврат только относительно исходной успешной операции с учётом уже возвращённого и ожидающего. Unknown означает «Проверяем результат», кнопка повторного возврата блокируется до сверки. Ручная запись требует факта получения денег и основания; файл гостя сам по себе не меняет баланс. Сторно сохраняет историю. Authorization залога не называется полученными деньгами; снятие блокировки не называется возвратом перечисленного залога.

## 4. Остальные рабочие сценарии

| Контекст | Последовательность и существенные решения |
|---|---|
| Объекты | Объект/категория/единица разделены; вместимость, часовой пояс и правила до продаж. Архив при будущих бронях показывает связи и блокирует потерю размещения. Фото загружает владелец с правами; в комплекте нет вымышленных фото реального жилья. Карта имеет альтернативный список. |
| Массовые цены | Объекты + диапазон + дни недели + правило → таблица до/после и число ночей → подтверждение. Ошибки min/max, stop-sell и неподдерживаемые ограничения канала видны по строкам. Повтор не применяет скидку второй раз. |
| Гости/документы | Минимальные поля профиля; телефон не уникальный идентификатор человека. Сходные профили сравниваются перед объединением с журналом. Документы открываются по отдельному праву, с аудитом; не включаются в общие таблицы или уведомления. Основания/цели/версии согласий раздельны. |
| Кабинет гостя | Только собственная бронь по проверенной ограниченной сессии; даты, адрес, условия, баланс, доступные платежи/документы и связь. Никаких ID других клиентов в URL-ответе. Истечение ссылки предлагает безопасное обновление доступа. |
| Сообщения | Шаблон → безопасный предпросмотр → получатель/канал → отправка → журнал статусов. Входящее сообщение не означает поддержанную обратную отправку конкретного OTA. Unknown не называется доставкой; повторы подчинены паспорту провайдера. |
| Каналы | Карточка показывает механизм API/iCal, поддержанные операции, доступ/договор, последние попытку и успех. Feed URL и токены секретны. До допуска нет рабочего переключателя синхронизации. iCal не имеет ложных полей отправки цен/оплат. |
| Конфликт обмена | Две исходные версии и поля под управлением сторон → ответственный → варианты размещения/согласование → запись решения → сверка. Событие не удаляется. Локальный stop-sell не обещает мгновенной остановки внешних продаж. |
| Миграция | Файл → проверка типа/колонок → сопоставление → dry-run → расхождения → подпись ответственного → пробный импорт → сверка → переключение. Незаполненный статус/ID/валюта не заменяются догадкой. Финансовые данные не восстанавливаются из комментария. |
| Подписка | Версия плана, единицы лимитов, дата следующего счёта, состояние, состав итоговой суммы. Цены задаются бизнесом до платного запуска. Превышение объясняется до добавления; данные доступны на чтение/экспорт согласно политике. Входящие оплаты/OTA-события не отбрасываются после ограничения UI. |
| Команда | Выбор роли + объектов + обзор фактических прав перед приглашением. Запретить удаление последнего владельца. Отзыв прекращает доступ с серверной проверкой каждого запроса. Не называть скрытую кнопку защитой данных. |
| Задачи | Исполнитель видит назначенный объект/срок/чек-лист; фото и комментарий → завершить → принять либо доработка. Готовность уборки не доказывает финансовую готовность к заезду. Начисления сотрудникам не равны банковской выплате. |
| Поддержка | Причина/заявка/организация/разрешённые операции/срок доступа → аудит → отзыв. У администратора SaaS нет постоянного общего просмотра гостевых документов. Метрики контроля показываются отдельно от бизнеса арендатора. |

## 5. Общая система состояний

Каждый канонический экран наследует строки ниже. Специальные варианты указаны в [screens.json](screens.json). Общие состояния дополняют конкретные поля, а не заменяют их макет.

| Состояние | Отображение и действие | Фокус/данные |
|---|---|---|
| Первичная загрузка | Статичный скелетон с реальной геометрией, подпись; без мигающего shimmer | aria-busy; фокус не перемещается |
| Обновление | Сохранить старую таблицу, индикатор рядом с временем; действия по устаревшему требуют новой проверки | Не сбрасывать фильтры/скролл |
| Нет записей | Причина и одно действие по роли: создать/импортировать/назначить | Не предлагать недоступную запись |
| Пустой поиск | Показать фильтры и «Сбросить фильтры» | Возврат в поле поиска |
| Ошибка чтения | Понятный текст, повтор, доступное время последнего чтения | Не раскрывать внутренний stack/ID чужой записи |
| Офлайн/устарело | Баннер с моментом обновления, read-only; кнопка повторной проверки | Черновик остаётся в памяти сессии; новые операции недоступны |
| Сохранение | Кнопка занята; другие повторные команды недоступны | Состояние не сбрасывать по одному timeout |
| Успех | Тихое inline подтверждение/тост с ссылкой на запись/историю | Не открывать лишний диалог; объявить aria-live polite |
| Валидация | Поле + краткий список; подсказать исправление | Первый неверный элемент; aria-describedby |
| Нет прав | Причина в общих терминах; обратиться к администратору/назад | Не сохранять ранее открытые запрещённые данные |
| Не найдено | «Запись недоступна или удалена» + к списку | Единый ответ для чужого tenant |
| Версия изменилась | Сравнение доступных полей «ваше/текущее»; перенести выбранные изменения | Не затирать сервер автоматически; повторная проверка |
| Конфликт дат | Объект, разрешённые детали пересечения, новые даты/подбор | Нельзя «всё равно сохранить» |
| Лимит/истёкшая подписка | Лимит/дата/доступные действия и переход владельцу | Приглашённый менеджер не платит от лица владельца |
| Нет доступа к интеграции | Конкретный договор/право/операция и ответственный | Нет кнопки, создающей видимость активного обмена |
| Неизвестный результат денег/доставки | Сверка и журнал, никаких ложных галочек | Повтор только после определения безопасного действия |

Закрытие dirty формы требует выбора «Продолжить редактирование»/«Закрыть без сохранения». Browser unload — страховка, не единственный путь. Навигация не теряет черновик молча. Диалог опасного действия ставит начальный фокус на заголовок/безопасное действие, Escape отменяет до отправки. После отправки Escape закрывает просмотр, но не отменяет уже принятую сервером операцию.

## 6. Компоненты

| ID | Варианты и обязательное поведение |
|---|---|
| CMP-BUTTON | primary/secondary/text/danger/icon; default/hover/pressed/focus/disabled/busy. Один primary на область решения. Надпись действие+объект; busy сохраняет ширину. |

## 7. Адаптивность и доступность

Широкий ≥1600 px: календарь и правая сводка заездов/задач; ширина дня остаётся читаемой. Обычный 1280–1599: полное меню и карточка поверх части календаря. Планшет 768–1279: меню в панели, даты/объекты закреплены, второстепенные колонки убраны в раскрытие строки. Мобильный 360–767: стартовый список дня, фильтры полноэкранные, карточка отдельной страницей, таблицы как семантические строки с названием/главными полями; денежные/аудитные таблицы имеют помеченную горизонтальную прокрутку. Детальная шахматка доступна по выбору, не сжимается до нечитаемой сетки. Значимые действия не скрыты только в hover.

Минимум 360 px; проверочные макеты 390×844, 1024×768, 1440×960 и 1920×1080. При 200% zoom двухколоночные формы переходят в одну колонку; 400%/320 CSS px reflow кроме обоснованно двумерной шахматки. Нижняя мобильная навигация и клавиатура не перекрывают последнее поле, padding safe-area. Суммы/даты не обрезать в ключевых решениях.

Цель WCAG 2.2 AA, [официальные критерии W3C](https://www.w3.org/TR/WCAG22/). Текст ≥4.5:1, крупный ≥3:1; активные границы/фокус ≥3:1. Тонкая серая линия декоративна, ошибки и фокус имеют контрастную обводку. Голосовые метки русские. Фокус 2 px с отступом 2 px, не обрезан sticky областями. Визуальная кнопка desktop 36 px, интерактивная область минимум44×44 без перекрытий; mobile44. Формы label/description/error, таблицы caption/header, skip-link к основному содержимому, порядок заголовков. Системные браузерные сочетания не перехватывать. Tab идёт между группами календаря; стрелки перемещают активную ячейку, Shift расширяет, Enter открывает, Escape снимает. Объявление диапазона после выбора, не на каждый пиксель drag.

## 8. Визуальный язык, движение, исходники

Golos Text 400/500/600. Тело14/22, таблица13/20, подпись12/18, заголовок26/32; в мобильных полях16 для предотвращения автозума. Отступы4/8/12/16/24/32/48. Прямые таблицы и панели, радиусы4/5/8, без стекла, градиентов, декоративных 3D и избыточных карточек. Фото только конкретного объекта с правами. Для статуса используются семантические цвета из tokens.json. Иконки24 px, stroke1.75, всегда с названием либо доступной меткой.

Hover100 ms, изменение статуса150 ms, drawer180 ms, dialog120 ms, easing из токенов. Нет bounce, parallax, автоцикла и анимации цифр денег. Skeleton статичен. prefers-reduced-motion убирает перемещения, оставляя мгновенную смену. Анимация не задерживает подтверждение и не заменяет текст результата.

SVG содержит настоящий редактируемый текст и простые векторные примитивы. Установить локальный Golos Text, импортировать SVG в Figma/Inkscape; сохранить ID артборда и токены. PNG — контрольное представление, не исходник для реализации пикселей. Генераторы в tools создают только статичные материалы и не являются началом приложения. Все финансовые значения и даты в макетах иллюстративны; бизнес-правила выше визуального примера.
