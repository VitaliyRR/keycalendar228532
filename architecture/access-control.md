# Доступ и изоляция клиентов

Связь: REQ-IAM-001..005, REQ-ORG-001..003, REQ-OPS-003. Имена ролей ниже канонические; интерфейс использует русские названия. Проверки сервера обязательны для REST, worker, export, download, WebSocket/SSE и административного доступа.

«Да» всегда ограничено текущим tenant. Права на объект распространяются на его units, брони, строки отчётов и файлы. Роль owner не означает право смотреть ПД без необходимости: чувствительные документы выделены в операционное разрешение с audit. Партнёр не является сотрудником по умолчанию и не видит внутреннюю закупочную цену, чужих гостей, секреты и общий портфель.

## Проверка запроса

1. Проверить session, email verification, актуальную membership и permissions_version.
2. Tenant из маршрута должен принадлежать активной membership; игнорировать organization_id в body. Для webhook tenant находится по проверенному идентификатору подключения.
3. Вычислить permission+property scope; фильтровать до pagination/агрегации. Для неизвестной или чужой записи вернуть одинаковый 404.
4. Начать транзакцию; поставить tenant context через SET LOCAL; db-role приложения не owner, не superuser и без BYPASSRLS. FORCE RLS там, где применимо. Для worker тот же контекст.
5. Составные FK предотвращают ссылку на гостя/объект другого tenant. Ошибки ограничений переводятся в безопасный код, без чужих значений.
6. Аудит, outbox и доменная запись фиксируются совместно. Ответ/файл содержит только разрешённые поля.

RLS имеет исключения для владельцев таблиц, superuser и BYPASSRLS: [документация PostgreSQL](https://www.postgresql.org/docs/18/ddl-rowsecurity.html). Поэтому тесты запускаются с реальной ролью приложения и пулом соединений, включая повторное использование соединения двумя tenant.

## Вход и жизненный цикл

Пароль: Argon2id с параметрами, измеренными на целевом сервере; исходный пароль не логируется и не возвращается. Session cookie Secure/HttpOnly/SameSite=Lax; CSRF для браузерных изменений; idle 12 часов, absolute 7 дней; MFA повышает auth_level на 10 минут. Ограничение попыток на IP+account, ответ восстановления одинаковый для существующего и отсутствующего email. Подтверждение email 24 часа, recovery 30 минут, invitation 72 часа. Токены одноразовые и в БД хэшируются. Основа выбора: рекомендации [OWASP по паролям](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html) и [сессиям](https://cheatsheetseries.owasp.org/cheatsheets/Session_Management_Cheat_Sheet.html), проверены 24.09.2026; конкретные TTL являются нашими допущениями.

Повторная регистрация не раскрывает наличие адреса. MFA recovery codes хранятся хэшами и используются один раз. Изменение пароля отзывает другие сессии; отзыв membership немедленно запрещает новые API-команды, открытые вкладки получают 403 ACCESS_REVOKED. Последнего owner нельзя удалить/понизить; передача требует verified получателя и MFA обеих сторон. Имперсонация поддержки по умолчанию запрещена.

## Секреты, ПД и аудит

Ключи интеграций и шифрования вне Git и business tables, в секрет-хранилище с версионированием; worker получает только нужный канал. Ротация использует overlap двух версий только если провайдер поддерживает; иначе планируемая замена с паузой исходящей очереди. Raw webhook сохраняется в закрытом хранилище с TTL 30 дней (проектное значение) и маскированием журналов. Search hash ПД использует tenant-specific HMAC; слабые хэши телефонов запрещены.

Аудит содержит actor, org, action, resource, time, correlation, reason, whitelist diff; пароли, токены, полные документы, телефоны и тела сообщений исключены. Журнал append-only, ежедневный подписанный digest в отдельном bucket; удаление/доступ администраторов также журналируется. Экспорт получает временную ссылку на download endpoint приложения ≤ 10 минут; endpoint при каждом скачивании проверяет текущую сессию/роль и отдаёт поток из private storage, не раскрывая прямой S3 URL. Файл удаляется через 24 часа. Support grant виден owner, имеет причину, TTL ≤ 1 час, read-only по умолчанию и не даёт скачивание ПД.

Офлайн-календарь REQ-CAL-009 хранит только явно разрешённый минимальный снимок занятости без контактов, документов, финансов и кодов. Отдельный endpoint offline snapshot, opt-in на устройстве, tenant+user scope, TTL ≤24ч и очистка при logout/switch/revoke, когда клиент выходит в сеть. Офлайн права нельзя отозвать на физически отключённом устройстве мгновенно, поэтому чувствительные поля не кэшируются и запись недоступна. Обычные ответы ПД имеют no-store.

## Обязательные негативные проверки

Соседний tenant UUID в path/body/FK; разные tenant в одном batch; чужой object storage key; утечка через count/search/report; user с удалённой membership в очереди; scope с нулём объектов; смена роли в открытой вкладке; session fixation; CSRF; повтор invitation; recovery token replay; support grant expiry; restored backup с выключенной RLS. Каждый сценарий должен завершаться отказом без записи чужих данных и без раскрытия их содержимого.
