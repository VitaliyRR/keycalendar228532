# PostgreSQL integration tests

`postgres.integration.test.ts` запускается командой `npm test -w @keycalendar/api`. Если `TEST_DATABASE_URL` не задан, сценарий пропускается. Если URL задан, недоступная БД, отсутствие миграций, неверная роль или нарушение инварианта приводят к ошибке теста.

Нужна отдельная тестовая PostgreSQL с примененными миграциями `apps/api/migrations`. URL должен указывать на runtime роль без SUPERUSER и BYPASSRLS, с доступом к тестовым таблицам. Миграции применяются административным подключением через `DATABASE_MIGRATE_URL`; `DATABASE_APP_PASSWORD` задает пароль runtime роли `keycalendar_app`. В тестах используются только синтетические UUID, адреса `example.test` и данные, удаляемые после проверки.

Проверяются FORCE RLS, принадлежность записей текущей организации, составной внешний ключ, отсутствие утечки `SET LOCAL` в пуле соединений, исключающее ограничение при двух одновременных бронированиях и идемпотентность команд при повторах и конкуренции. Тесты не обращаются к действующей ВМ, RealtyCalendar или внешним каналам.
