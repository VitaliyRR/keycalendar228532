# INT-MONETA-PERSONAL. Монета для физических лиц

Проверка: 2026-09-24. Статус источника: `DOC`. Кей Календарь: `external_access_pending`.

Назначение: приём и сверка платежей

Источник: [официальная инструкция / публикация](https://confluence.lan.realtycalendar.ru/kb/podklyuchenie-moneta-dlya-fizicheskih-lits-30958553.html).

## Подтверждение и подключение

Механизм: **partner payment integration; wire protocol unknown**.

В RC / у поставщика: Телефон/банк СБП и оферта в действующей процедуре RC.

Предоплата, полная оплата, залоги и возвраты; личные карты/счета, не бизнес-карты. RC указывает 1,22% на возврат залога и 3,5%+40 ₽ при удержании; это условия продукта RC, договор Кей Календаря не известен.

Право Кей Календаря подключаться не подтверждено. Получить договор/партнёрский допуск и актуальную спецификацию у поставщика; не использовать имя или ключ RC как собственный provider. Стоимость нового подключения, комиссия, SLA, rate limits и sandbox неизвестны, пока поставщик не выдаст условия. Указанные в наблюдении суммы относятся только описанному продукту RC, не нашей себестоимости.

## Направления обмена

| Сущность / операция | Направление и предел подтверждения |
|---|---|
| Брони / отмена брони | Не синхронизируются как OTA; reference связывает платёж с бронью |
| Доступность / цены / ограничения | not_applicable |
| Создание платежа / возврата | Кей Календарь → провайдер: PROPOSED, только после собственного договора |
| Статус оплаты / возврата / выплаты | Провайдер → Кей Календарь: PROPOSED, webhook + fetch/reconciliation по выданному контракту |
| Чеки | Отдельная сущность с самостоятельными статусами; поддержка по продукту и договору |

## Доставка, задержка и тестовая среда

Webhook, polling, подпись, частота, квоты запросов и максимальная задержка нового соединения неизвестны до спецификации поставщика. Нельзя подменять бизнес-задержку модерации задержкой транспорта. План пилота должен замерять время получения и применения событий отдельно. Sandbox в использованной инструкции не подтверждён; запросить тестовый tenant/объект и план сертификации.

## Сопоставление, ошибки и восстановление (PROPOSED)

Все технические правила ниже являются требованиями Кей Календаря (PROPOSED), а не описанием внутренней реализации RC.

Применить [INT-CORE-002–007](../contract.md): tenant-scoped connection и external IDs; durable inbox/outbox; dedup по событию и внешней сущности; контроль версии; обнаружение конфликтов; 401/403 переводит соединение в переавторизацию; 429/5xx повторяются по правилам провайдера; 4xx validation требуют исправления. Неизвестный результат финансовой/кодовой операции сначала сверяется, затем повторяется. Маскированные логи, correlation ID, DLQ, checkpoint/reconciliation, audit ручного восстановления обязательны.

Дополнительное условие для Монета для физических лиц: проверить указанные выше особенности на отдельном объекте и записать результат в capability matrix перед включением.

## Конкретный следующий шаг и приёмка

1. Владелец интеграций направляет поставщику Монета для физических лиц заявку именно от Кей Календаря: модель multi-tenant PMS, целевые объекты/страны, нужные операции, sandbox, коммерческие условия. В ходе текущего исследования заявки не отправлялись.
2. Получить письменный допуск, schema/auth/rate limits/доставку/retention и заполнить unknown; для исторических упоминаний сначала подтвердить существование действующего продукта.
3. Реализовать только согласованные capabilities; выполнить применимый набор [INT-CORE-008](../contract.md). Отсутствующая возможность имеет состояние «Не поддерживается», недоступный допуск «Ожидает доступа».
4. Проверить mapping, конфликт, потерю/повтор события, отзыв ключа, восстановление и изоляцию клиентов. Зафиксировать реальные задержки и runbook. До этого коннектор не готов к production.

Связь с реализацией: паспорт `INT-MONETA-PERSONAL` является самостоятельным scope для задачи подключения; общие требования `INT-CORE-001`…`009`; экран интеграций и журнал синхронизации, карточка брони. Общий порядок: допуск → adapter → контрактные проверки → тестовый объект → пилот → подключение клиента.
