Назначение: канал бронирования

Источник: [официальная инструкция / публикация](https://confluence.lan.realtycalendar.ru/kb/sinhronizatsiya-s-avito-30958424.html).

Официальная точка технической проверки: [Avito Developers, краткосрочная аренда](https://developers.avito.ru/api-catalog/short-term-rent/documentation). Страница из исследовательской среды недоступна, поэтому её текущие endpoint, scopes, sandbox и коммерческий допуск не считаются проверенными. В исследованном аккаунте карточка Avito показывает аккаунт, ID объявления, наценку и комиссию (ACC-CHAN-01); наличие карточки не доказывает успешный текущий обмен.

## Подтверждение и подключение

Механизм: **API (RC); KeyCalendar access pending**.

В RC / у поставщика: Авторизация аккаунта на Avito, номер объявления.

В RC не поддержаны комната, номерной фонд и квотируемые объявления. Бронь поступает после модерации оплаты: RC указывает 3 секунды–24 часа, это не SLA транспорта. Контакты могут приходить позднее. CTA/CTD превращаются в полное закрытие дня. Ручная правка OTA-брони может быть перезаписана.

Право Кей Календаря подключаться не подтверждено. Получить договор/партнёрский допуск и актуальную спецификацию у поставщика; не использовать имя или ключ RC как собственный provider. Стоимость нового подключения, комиссия, SLA, rate limits и sandbox неизвестны, пока поставщик не выдаст условия. Указанные в наблюдении суммы относятся только описанному продукту RC, не нашей себестоимости.

## Направления обмена

| Сущность / операция | Направление и предел подтверждения |
|---|---|
| Брони / изменения | Площадка → RC по общим принципам API; поля и подтверждение получения для нового provider требуют schema |
| Отмены | Площадка → RC; локальная отмена → площадка не подтверждена. После заезда требуется сверка |
| Доступность / stop-sell | RC → площадка, если отмечено в таблице |
| Цены | RC → площадка, если отмечено в таблице |
| Ограничения | RC → площадка только для отмеченных возможностей; max stay неизвестен, кроме отдельно подтверждённых |
| Гости / оплаты | Только доступные поля входящей брони; обновление платежа не равно гарантированной финансовой сверке |
| Создание объявлений / фото / отзывы / чат | Не подтверждено; не включать автоматически в native capability |

## Доставка, задержка и тестовая среда

Webhook, polling, подпись, частота, квоты запросов и максимальная задержка нового соединения неизвестны до спецификации поставщика. Нельзя подменять бизнес-задержку модерации задержкой транспорта. План пилота должен замерять время получения и применения событий отдельно. Sandbox в использованной инструкции не подтверждён; запросить тестовый tenant/объект и план сертификации.

## Сопоставление, ошибки и восстановление (PROPOSED)

Все технические правила ниже являются требованиями Кей Календаря (PROPOSED), а не описанием внутренней реализации RC.

Применить [INT-CORE-002–007](../contract.md): tenant-scoped connection и external IDs; durable inbox/outbox; dedup по событию и внешней сущности; контроль версии; обнаружение конфликтов; 401/403 переводит соединение в переавторизацию; 429/5xx повторяются по правилам провайдера; 4xx validation требуют исправления. Неизвестный результат финансовой/кодовой операции сначала сверяется, затем повторяется. Маскированные логи, correlation ID, DLQ, checkpoint/reconciliation, audit ручного восстановления обязательны.

Дополнительное условие для Авито: проверить указанные выше особенности на отдельном объекте и записать результат в capability matrix перед включением.

Специальные сценарии приёмки: бронь ожидает модерации → подтверждена; новые контакты после окончания бесплатной отмены не создают дубль; гостевая корректировка дат не стирает локальную заметку; локальное переселение создаёт конфликт инвентаря, а не молчаливую подмену исходного объявления. При CTA/CTD интерфейс требует явного решения о полном закрытии даты вместо неверного отображения точной поддержки. Квитанция/комиссия площадки сверяются с расчётным реестром, скидка площадки может отличаться от отображённой RC комиссии.

## Конкретный следующий шаг и приёмка

1. Владелец интеграций направляет поставщику Авито заявку именно от Кей Календаря: модель multi-tenant PMS, целевые объекты/страны, нужные операции, sandbox, коммерческие условия. В ходе текущего исследования заявки не отправлялись.
2. Получить письменный допуск, schema/auth/rate limits/доставку/retention и заполнить unknown; для исторических упоминаний сначала подтвердить существование действующего продукта.
3. Реализовать только согласованные capabilities; выполнить применимый набор [INT-CORE-008](../contract.md). Отсутствующая возможность имеет состояние «Не поддерживается», недоступный допуск «Ожидает доступа».
4. Проверить mapping, конфликт, потерю/повтор события, отзыв ключа, восстановление и изоляцию клиентов. Зафиксировать реальные задержки и runbook. До этого коннектор не готов к production.

Связь с реализацией: паспорт `INT-AVITO` является самостоятельным scope для задачи подключения; общие требования `INT-CORE-001`…`009`; экран интеграций и журнал синхронизации, карточка брони. Общий порядок: допуск → adapter → контрактные проверки → тестовый объект → пилот → подключение клиента.
